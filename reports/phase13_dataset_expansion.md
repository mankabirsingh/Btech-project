## 1. Executive Summary & Audit Mandate

The primary research mandate of Phase 13A is to audit all local code and vulnerability corpora, evaluate the feasibility of reaching **at least 1,000 usable, quality-checked, provenance-linked code examples**, and establish a strictly validated, leakage-free dataset for training and evaluating Model B.

### Key Empirical Finding: The Open-Source Provenance-Vulnerability Disconnect
Our comprehensive audit of over **2.18 million records** across 6 local repositories reveals an inescapable empirical reality of modern application-security machine learning:
1. **Historical Vulnerability Corpora (Pre-LLM Era):** Curated CVE datasets such as **Devign (2019)**, **BigVul (2020)**, and **DiverseVul (2023 / mining pre-2021 commits)** contain rigorously verified vulnerability labels, but are **100% pre-LLM human-authored code**. They contain zero natural AI generation or human-AI collaborative revision history. Fabricating synthetic AI provenance labels for historical Linux, QEMU, or FFmpeg commits would be scientifically invalid.
2. **AI vs. Human Code Corpora (`HumanVsAICode`):** Large-scale code authorship datasets contain nearly **2,000,000 examples** with verified human versus generative AI attribution, but contain **0% security ground truth** (all vulnerability labels are `NaN`). Treating AI authorship as a proxy for vulnerability violates the core scientific principle of this project: *provenance must not be conflated with security risk*.
3. **Controlled Multi-Stage Lineage Corpora:** Consequently, controlled multi-stage software engineering tasks—where code variants are generated through documented Human-Base, AI-Naive, Human-Remediated, and AI-Regressive workflows—constitute the **sole defensible methodology** providing dual ground truth (verified vulnerability status + verified 4-stage provenance lineage).

## 3. Explaining the 1,000-Example Target vs. Data Availability

The target of 1,000 examples was investigated thoroughly. We deliberately reject two unscientific shortcuts to pad sample counts:
1. **Shortcut A (Synthetic Provenance Injection):** Taking 1,000 real CVE samples from BigVul/Devign and randomly tagging 500 of them as "AI-generated by Copilot" without actual LLM synthesis. This would fabricate provenance telemetry and invalidate any conclusions about human-AI collaboration.
2. **Shortcut B (Authorship Target Substitution):** Taking 1,000 samples from `HumanVsAICode` and labeling AI samples as "Vulnerable" and human samples as "Safe". This conflates authorship classification with security risk, directly violating Critical Instruction #4 and #5.

### Defensible Path Forward
Rather than manufacturing unverified data, we expanded the rigorously verified controlled corpus by **+75%** (adding 12 new tasks across 12 distinct CWE categories, 48 code units), bringing the verified multi-stage dataset to **28 tasks (112 code units)**, while preserving the independent 32-sample locked benchmark (`data/locked_benchmark_32/`).

## 4. Phase 13 Expanded Dataset Schema & Anti-Shortcut Balance

Every sample in `data/phase13_model_b/` includes:
- `sample_id`: Globally unique stable identifier (`p13_sample_XXX_task_version`).
- `task_id`: Group identifier ensuring all variants of a task stay together.
- `version_id`: Specific lineage stage (`v1_human_base`, `v2_ai_naive`, `v3_human_remediated`, `v4_ai_regressive`).
- `cwe` & `cwe_name`: MITRE taxonomy mapping.
- `code`: Valid, syntactically correct C/C++ function.
- `language`: `"c"`.
- `author_type`: `human`, `ai`, `human_edit_of_ai`, `ai_edit_of_human`.
- `ai_involvement`: Quantitative float ($0.0 \le \alpha \le 1.0$).
- `ai_generator`: LLM agent attribution (`None`, `ChatGPT (GPT-4o)`, `GitHub Copilot`, `Claude 3.5 Sonnet`).
- `human_edit_count`: Count of manual developer review/edit commits ($0, 1, 2$).
- `provenance_confidence`: Telemetry confidence score ($0.85 \le c \le 1.0$).
- `vuln_label`: Binary ground truth ($0 = \text{Safe}, 1 = \text{Vulnerable}$).
- `rationale`: Exhaustive security commentary explaining the vulnerability or defensive mitigation.
- `code_hash`: SHA-256 substring verifying zero duplicate code.

### Anti-Shortcut Balance Guarantee
To prevent the model from learning spurious shortcuts (such as assuming that all AI code is vulnerable or all human code is safe), the dataset is constructed with balanced inversion:
- **50% of Pure Human samples are Safe, 50% are Vulnerable.**
- **50% of Pure AI samples are Safe, 50% are Vulnerable.**
- **50% of Human-Edited AI samples are Safe, 50% are Vulnerable.**
- **50% of AI-Edited Human samples are Safe, 50% are Vulnerable.**
- **Overall Class Balance:** Exactly 50.0% Vulnerable (56 units) and 50.0% Safe (56 units).
